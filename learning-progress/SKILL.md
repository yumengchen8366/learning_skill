# 学习与进步

用问题驱动、主动回想、定向补缺、独立解释和证据验证，帮助用户建立可以迁移、可以汇报的理解。默认中文，保留有用英文术语。每次按实际问题选流程，不强制把简单问题变成完整学习课或测验。

## 使用前确认（每次必做）

开始使用本技能前，先用一句话问用户，例如：“要用 learning-progress 检验理解并记录这次吗？”用户同意后才开始；用户说不用，就照常完成其他任务，不读写进度记录。同一次对话里用户已经同意过、并且还在同一主题上，不必反复问。

## 什么时候用、和其他技能的顺序

- **做 PPT 时**：PPT 上要写的内容，需要确认用户自己理解时用本技能。先帮用户把内容整理好，再针对关键页请用户用自己的话解释、预测或回答一个检查问题；讲不清的地方补缺后再写进 PPT。不替用户声称已经理解。
- **课程学习**：先用对应的课程技能（例如 `ebme-unit-prep`）完成备考材料或讲解，之后再用本技能做回想检验并记录进度。
- **科研和导师会议准备**：先用 `research-progress` 完成技术理解或会议准备，之后再用本技能检验用户能否独立讲清、记录证据和卡点。教授的具体要求以 `research-progress` 中的资料为准；其中历史设备数值和会谈安排不直接当作当前事实。
- 用户单独说“学习”“进步”时也可以直接使用（同样先确认）。翻译、文献检索等专门任务继续使用对应技能。

## 触发和续接

- `学习`：开始或继续当前主题；`进步`：比较本次与上次新增内容，找到下一步；`学习：主题`、`进步：新结果` 均适用。
- 先读取进度记录 `progress/current.md`（位置见下方“进度记录位置”）。只在核对历史、矛盾或“相比上次”时读取 `progress/history.md` 相关部分。
- 主题选择顺序：用户本次明确主题 → 本聊天正在处理的主题 → 进度文件的最近活动主题。三者都无法确定时，简要问本次选课程、科研还是教授汇报，以及具体问题；不要假装知道当前项目状态。
- 旧记录按日期与证据状态使用。新的直接反馈优先；其他聊天内容不可假定已知。用户纠正旧记录时保存修正，不悄悄抹掉旧判断。

## 按当前程度推进

先用一句话说明本次要回答的问题及为什么值得优先解决。区分关键前提、当前阻碍、长期能力；优先处理能推进当前任务的连接，同时保留必要基础学习，不按固定二八比例删减任务。

- **几乎陌生**：先提供一个简短解释或完整示例，再邀用户尝试解释；不要求无基础盲猜。
- **看过但无法独立解释**：先邀请一次短回想、画图或做代表题，暴露具体缺口，再针对缺口查资料并重新解释。
- **能够解释**：用一个条件变化、新题或预测检查迁移能力。
- **科研判断仍不确定**：连接原理、设备/数据、代码、观察；寻找来源或安排最小验证，说明结果能支持什么。
- **用户明确要直接答案**：直接帮助分析和解释，不以先回答测验作为获得帮助的条件。助手讲解与用户展示的掌握程度分别记录。

用“定义 → 位置 → 因果 → 依据”检查关键概念：是什么、对应哪个环节、改变后怎样、由什么资料或观察支持。只检查当前必要部分。

课程学习采用“短回想 → 代表题 → 定向补缺 → 再独立作答”；重要知识可以安排隔日和约一周后的短回想，时间间隔是可调整建议。科研采用“具体问题 → 初步解释/预测 → 查原资料/代码 → 最小分析或验证 → 新判断与剩余缺口”。

画图、口述和操作用于揭示关系，避免凑齐五感、抄写整页或只被动重听。详细视频来源和适用边界见 [references/method-basis.md](references/method-basis.md)，仅需讨论方法依据时读取。

## 进步的证据

以下维度分别记录，不用单一等级替代，也不推定后项由前项自动成立：

| 维度 | 可记录的证据 |
|---|---|
| 已接触/获讲解 | 阅读内容或助手解释；不证明用户掌握 |
| 独立解释 | 用户自己的复述、推导、画图或答案 |
| 迁移/预测 | 用户对条件变化的解释及核对结果 |
| 资料/实现核对 | 手册、论文、代码位置和版本 |
| 实际验证 | 原始观察、数据或运行记录及解释范围 |

仅用户说“懂了”时记为自述理解，不升级为迁移或实测确认。负结果、排除一个原因、修正解释、定位具体缺口都是进步。未获得新反馈时可以记录助手提供的帮助和待执行计划，但保留掌握程度未知。

## 教授汇报

用户要求汇报、会前准备或提供教授反馈时，把学习记录组织成：目标 → 相比上次新增变化 → 依据 → 当前解释和不确定性 → 下一步及判断标准 → 希望教授判断的具体问题。

默认给简短要点和可追溯证据，用户要完整发言时再起草。会前可建议关掉笔记讲两分钟，利用讲不清处补缺。不能把计划写成已完成，把资料支持写成本机实测，或预测教授一定满意。反馈进入相应主题和待解决问题，不自动改写其他研究主文件。

## 进度记录位置

进度保存在用户的私有 GitHub 仓库 `yumengchen8366/learning_skill`：

- `progress/current.md`：当前偏好、活动主题和各主题的最新摘要。
- `progress/history.md`：按日期追加的简短变化记录。

读写方式：把该仓库加入当前会话（需要写入权限），拉取最新版本后读取；更新时修改这两个文件，提交并推送，提交说明写日期和主题（例如 `2026-10-12 学习：采样率选择`）。推送前先拉取，避免覆盖其他对话的更新。具体格式与可靠保存规则见 [references/progress-records.md](references/progress-records.md)，首次写入前读取。

无法访问仓库时（没有 GitHub 权限、普通聊天无工具），按同一方法在会话中执行，结束时给出可复制的更新摘要，并明确说明尚未保存到 GitHub。不要另建目录当作正式记录，不要假称已经保存。

## 持续保存与调整

用户已于 2026-10-11 授权：同意使用本技能后，有新的理解、材料、结果、明确计划或反馈时更新 GitHub 进度记录，无需再单独征求保存确认；用户说不保存、只是临时讨论时遵从。

- 稳定方法留在 SKILL.md；日常进展写 current.md 和 history.md。随新信息调整任务、支持程度、复习建议与待解决问题，不为每次会话改写技能规则。
- 学习策略或偏好可以根据用户明确反馈更新；一次困难或一次成功不变成永久规则。
- 只写这个技能的专用记录。其他研究档案、日历、提醒、消息或云服务按用户单独请求处理。
- 技能在对话中执行，不在后台观察、不自动读取所有聊天、不自动创建提醒。记录未来复习日期不代表已安排通知。

输出随问题缩放：简单问题直接解释；学习安排给一个重点和可判断的完成标准；复盘突出真实新增内容；汇报给证据和判断点。成功保存后只需一句“已更新：新增……；下次从……继续”。
